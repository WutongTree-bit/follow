# 券商档案（qcc 模块）

把企查查 MCP 的数据接进站点：每家券商（`industry/topics.json` 里的公司主题）有一页档案，分“企业数据”“法律数据”“标讯数据”三个标签。

| 地址 | 内容 |
|---|---|
| `/topics` 的“券商公司” | 券商列表，替换了主题页里这一组原来的卡片：搜索，卡片上是法定代表人、注册资本、风险因子和中标数，右上角标出“已建档”或“待建档”（有没有企查查数据），点进去是档案页 |
| `/brokers/<主题 slug>` | 一家券商的档案，默认打开第一个标签“相关动态”（这家券商的精选新闻，`?page=2` 翻页）；`?tab=company`、`?tab=legal`、`?tab=tender` 打开企业、法律、标讯数据 |
| 公司主题页 | 页头下方多一张“工商档案”卡片，链到档案页 |
| `/admin/qcc` | 后台“数据 → 企查查 MCP”：配置、连通测试、确认每家券商的工商主体 |

## 接入

1. 在企查查（agent.qcc.com → API Key）复制 `mcpServers` 配置，粘贴到后台“企查查 MCP”保存。令牌只存在数据库的 `settings`（`qcc.mcp`），页面只显示掩码，不要写进代码或 `.env`。
2. 点“测试连接”，每个服务应列出工具数；账号没开通的服务（例如 `qcc-history`）会显示企查查给的原因，模块不用它。
3. 点“识别全部未建档”。企查查规定：名称匹配到多家公司时必须由人选择，不能自动取第一个。名称正好是“券商名 + 公司形式”的候选标 ★，核对后可以“确认全部建议”，其余逐家选择。
4. 确认后会自动拉取一次数据。

## 数据怎么更新

- 读者打开页面不调用企查查：档案页发现数据缺失或超过 3 天（`backend/config.ts` 的 `CACHE_DAYS`）时，只往队列 `qcc.refresh` 放一个任务，由 worker 拉取，页面每 4 秒问一次进度。
- 一家券商完整拉取约 15 次工具调用（`backend/catalog.ts` 列出每个标签用哪些工具）。每次调用都记回执，计入“设置 → 付费请求上限”里的 `qcc` 额度（保存配置时创建，默认每分钟 30、每小时 600、每天 3000 次）；额度用完时保留旧数据，稍后重试。
- 失败的一块显示企查查给的原因，其余照常显示；整次失败后 30 分钟内的访问不再重试，管理员可以在后台“刷新数据”。

## 文件

| 文件 | 内容 |
|---|---|
| `contract.ts` | 接口与页面共用的类型 |
| `backend/config.ts` | 读取、保存、掩码 MCP 配置 |
| `backend/client.ts` | MCP 调用（经过回执与额度） |
| `backend/catalog.ts` | 每个标签调用哪些工具 |
| `backend/entities.ts` | 券商 → 工商主体的识别与确认 |
| `backend/refresh.ts` | 拉取任务与概览 |
| `backend/read.ts`、`backend/admin.ts` | 页面与后台读取 |
| `api/routes.ts` | `/api/qcc/*`（公开）与 `/api/admin/qcc/*` |
| `web/` | 档案页、各类数据的展示、主题页的券商列表与卡片 |
| `migrations/` | `qcc_entities`、`qcc_sections` 两张表 |
